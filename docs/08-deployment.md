# Сборка и развёртывание

`pnpm install --frozen-lockfile`, затем `pnpm build`; результат Vite находится в `dist/` (`package.json`, `vite.config.ts`). По текущей конфигурации приложения переменные окружения не используются. Реальный сервер не требуется.

## Vercel: предложение

1. Импортируйте репозиторий в проект статического хостинга.
2. Выберите установку `pnpm install --frozen-lockfile`, команду `pnpm build` и выходной каталог `dist`.
3. После публикации откройте адрес, проверьте загрузку ресурсов, выбор клиента и сохранение после обновления.

## GitHub Pages: предложение

1. Выполните установку зависимостей и сборку в CI.
2. Для адреса вида `https://<owner>.github.io/<repository>/` задайте при сборке базовый путь Vite, например `pnpm exec vite build --base=/<repository>/`, предварительно выполнив проверку TypeScript `pnpm exec tsc -b`. Текущий `vite.config.ts` не задаёт base и использует корень; для пользовательского домена обычно подходит корень.
3. Опубликуйте содержимое `dist/` через механизм Pages и проверьте страницу и загрузку CSS/JS.

Точные настройки площадок зависят от их текущего интерфейса. В проекте нет готового workflow публикации (`vite.config.ts`, `package.json`).

Рабочие правки хранятся в localStorage под `decision-radar-v1`, подтверждённая имитация CRM — под `decision-radar-simulated-crm-v1`, тема — под `decision-radar-theme` (`src/api/crmApi.ts`, `src/main.tsx`). Кнопка сброса приложения удаляет рабочую копию и возвращает базовую; для возврата к исходному JSON нужно удалить обе первые записи через инструменты разработчика браузера и обновить страницу. Удаление необратимо для локальных правок.

## Результат и границы

Ручной путь работает: карта или карточка → наблюдение с контекстом → проверка исходного фрагмента → сохранение → источник на карте → возврат. `InteractionEntry.tsx` — самостоятельный ручной вход для проверки интеграции до B, без извлечения текста и назначения роли. При подключении полноценной формы B его нужно заменить либо оставить как явно выбранный ручной режим, не дублировать два редактора одного интервью.

Одна запись и необязательный `EvidenceChange` подготавливаются без изменения исходного объекта и сохраняются одним `localStorage.setItem`. Zustand обновляется сразу после успешной записи, до искусственной задержки 150–400 мс. Следующий быстрый запрос читает последнее состояние. При отказе хранилища ни наблюдение, ни роль/сила не публикуются в состоянии. Старые формы также не закрываются с сообщением об успехе после отказа записи.

Повтор успешного запроса возвращает прежний ID. Тот же ключ с иным содержимым возвращает русскую ошибку. Пустые и отсутствующие массивы эквивалентны. Необязательные `CRMData.interactionRequests` хранят квитанцию в том же объекте, переживают перезапуск и подтверждение/сброс к локальной CRM. Старые записи без этого поля читаются. Квитанции не выводятся как поля diff. Общий контракт `SaveInteraction` сохранён.

Проверяются компания, контакты и ссылки, существующая календарная дата, будущая дата, автор/отдел/содержание, источник, даты измерения открытия и запроса согласования, допустимая роль и целая сила 1–5. Роль получает снимок на дату подтверждения, а не задним числом на дату интервью. Это не полная runtime-валидация произвольной импортированной CRMData.

`buildMapSlice` — единая граница компании и даты. Он сохраняет текущие связи с историческими людьми и скрывает будущие события, снимки и ещё неизвестные статусы открытия. Фильтры графа не меняют область данных. При смене компании/даты источник закрывается; старое сохранение не открывает чужую карточку. Недоступный источник объясняется уведомлением.

## Подключение B и C

В `App.tsx` передаются следующие props в существующие Incoming, PersonDetails, MeetingBrief и Integration через `sharedProps`. Пока компонент не объявил prop, он его не использует:

```ts
slice: MapSlice
companyId: string
today: string
selectedPersonId: string | null
initialPersonId: string | null
highlightedInteractionId: string | null
onSaveInteraction: SaveInteraction
onOpenSource(interactionId: string): void
```

Старые props сохранены. `onSaveInteraction(companyId, draft, change?)` берёт последнюю рабочую копию, проверяет действующую компанию и запрет исторического ввода и возвращает `SaveResult`. В форме удерживать `requestId` при повторе после ошибки, менять его при изменении содержимого. После успеха действие «Открыть на карте» вызывает `onOpenSource(result.interactionId)` только по нажатию пользователя.

Якоря A: `[data-tour="add-observation"]` — кнопка на карте; `[data-tour="observation-entry"]` — ручная форма; `.map-legend` — существующая легенда. C может прислать точный новый якорь/фрагмент. Бриф и метрики должны использовать `slice`, не исходную CRMData.

`?company=bank|retail|industry` задаёт начальную компанию. `?demo=2026-11-19` фиксирует только часы демосессии. Есть видимая кнопка включения/выключения демодаты; обычный режим берёт дату браузера. Пример интервью не присутствует в исходной истории до сохранения.

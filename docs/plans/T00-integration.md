# T00 — контракт и интеграция

**Версия 1, 19.11.2026.** Предлагаемый владелец — Виктор. База аудита `fafd69a`. Актуальный базовый commit потребителей записывается в [очереди](INDEX.md).

**Выход.** Явный контракт и один пример, на котором новая запись для выбранного человека переживает перезагрузку и становится доступна карточке и аналитике.

**Зона.** `src/types.ts`, `src/App.tsx`, `src/api/crmApi.ts`, `src/lib/crmDiff.ts`, `src/components/Integration.tsx`, `index.html`, сюда же правки общих маршрутов и документации. Не переписывать раскладку и библиотеку графа.

1. Ввести типы [контракта](../03-data-model.md#контракт-для-доработки). Отдать стабильный `onSaveInteraction(draft)` с результатом сохранения или читаемой ошибкой. Заранее согласовать с T02 точную сигнатуру и различить ожидание, успех и отказ. Пропсы карточки содержат историю с новыми полями, состояние исторического просмотра и готовые метрики, если расчёты подключаются на уровне App.
2. Запись идёт через текущий адаптер. Проверка и отказ до смены состояния, фиксация после успешного сохранения. Серия быстрых сохранений работает от последнего состояния. При отказе браузерного хранилища пользователь сохраняет введённый черновик. Смену клиента и историческую дату проверяем на момент записи. Не перезаписывать изменения другого клиента.
3. Начальная компания читается из валидного `?company=bank`, `retail` или `industry`, если хватает окна разработки. Точку входа из карточки CRM можно показать ссылкой на конкретного клиента в демонстрационной документации. Для неизвестного id работает обычный выбор. Раздел «Обмен с CRM» рисует локальную имитацию с выбранным клиентом и будущий контракт.
4. Показать diff по новой записи и проверить изоляцию клиента. На текущую дату редактирование доступно. При просмотре прошлого текст объясняет, что рёбра пока взяты из текущей схемы. В `index.html` дать короткое описание демонстрации и понятное сообщение при выключенном JavaScript.

**Приёмка.** Старый JSON и старый localStorage загружаются, поиск и редактирование действуют. Запись в клиенте A не появляется в клиенте B. После перезагрузки запись сохраняется, diff виден, поля истории по дате совпадают. Неуспешная запись не вызывает сообщение об успехе. `npm test`, `npm run build`. Сценарии S0 и S1 на интеграционной ветке.

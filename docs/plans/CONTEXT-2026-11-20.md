## 4. Что нельзя потерять в поведении

- Единый ввод интервью — EvidenceForm B через карту/карточку/предложение силы. Старый ручной интеграционный ввод A был промежуточным решением; не возвращать второй конкурирующий путь.
- SaveInteraction получает companyId, draft с requestId и необязательную EvidenceChange. Интервью, одна подтверждённая роль/сила и квитанция сохраняются одним CRMData. React получает состояние после успешной записи. Повтор успешного requestId открывает тот же interactionId; изменённое содержание с успешным ключом отвергается.
- Правку роли/силы надо подтвердить явно. initialChange лишь заполняет предложение, не устанавливает флажок. Подтверждение силы не создаёт новое независимое свидетельство о паре. Изменение роли датируется днём подтверждения, не прошлой датой интервью.
- Все источники открываются по interactionId в текущем MapSlice, а не по существованию человека в активном графе. Имя удалённого собеседника берётся из доступного снимка; контакт не возвращается на карту. Из чужой компании и до даты интервью запись недоступна.
- Канал состоявшегося касания — Interaction.channel; предпочтительный — evidence.preferences.channel. Инициатива/resumption/approval добавляются только выбранными флажками. requestedOn обязателен для approval и не позже даты касания. Срок — календарные дни, не рабочие.
- MapSlice задаёт компанию/дату до визуальных фильтров; показатели компании не пересчитываются по отфильтрованным людям. Удалённые авторы не стирают историю наблюдений.
- Чтение persisted JSON проходит crmValidation до миграции/React. Испорченная строка сохраняется побайтно в `${key}:recovery:${time}-${UUID}`. Если резерв не записался, оригинал остаётся на месте, поверх него писать нельзя. Корректные старые сохранения без snapshots мигрируют в памяти, не переписываются при загрузке.
- Все записи синхронизированы общей Web Locks-блокировкой origin. Простое интервью добавляется к актуальному состоянию, полная правка/подтверждённое изменение из устаревшей вкладки получает конфликт и сохраняет черновик. Две вкладки в регрессиях — независимые состояния с одним хранилищем.
- Канонические ключи: `decision-radar-v1`, `decision-radar-simulated-crm-v1`; данные отделены также origin и профилем браузера. HTTP/HTTPS и разные порты — разные рабочие копии. Не очищать пользовательские сохранения ради воспроизведения — брать отдельный профиль/origin.
- Исключения внутри callback Node 24 LockManager приводили к зависанию следующей блокировки. crmStorage возвращает outcome из callback и выбрасывает ошибку после освобождения. Не упрощать обратно без регрессии.

Основные владельцы файлов: API/валидация/хранилище — src/api; карта и source handlers — App.tsx / MapSlice; форма — EvidenceForm; источники — SourceRecord; показатели/сигналы — MapEvidence + lib; новый обзор — ContactOverview и read-only communicationPreferences. Типы и существующие расчёты редизайном не менялись.

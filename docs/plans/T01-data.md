# T01 — синтетические данные и метрики

**Версия 1, 19.11.2026.** Предлагаемый владелец — Марк.

**Зона.** `src/data/crm.json`, новый `src/lib/evidenceMetrics.ts`, отдельный тест метрик при необходимости. Общие типы и адаптер — T00. Существующие связи и идентификаторы сохранить.

**Выход.** В банке есть информативный контакт, две записи с предпочтением или сравнением поставщиков и измеряемые письма. Ритейл даёт сценарий пустого значения либо нуля. Данные для каждой компании полностью синтетические.

1. Согласовать с T00 [типы](../03-data-model.md#контракт-для-доработки). Использовать фиксированные даты демонстрации 19.11.2026. Пример письма с unknown исключить из знаменателя, добавить измеренные открытое и неоткрытое, показать проверяемое вручную число. Обозначить в отчёте контакты и даты для T04.
2. Подготовить валидные наблюдения, включая конкурента и причину перехода, явно заявленное предпочтение и упоминание контакта той же компании. Не помещать имена участников чата или настоящую обратную связь в демонстрационные данные.
3. Экспортировать чистый расчёт `calculateEvidenceMetrics(interactions, companyPersonIds, asOf, personId?)`, синхронизировать точные типы с T00/T03. Результат содержит начало и конец периода, числители и знаменатели, число открытий, число измеренных писем и состояние отсутствия данных. UI использует этот результат как источник данных.
4. Сведения за пределами периода, будущие даты и другой клиент исключаются. Дубликат id упомянутого человека в одной записи учитывается однажды. При `0 / 0` возвращаем отсутствие данных. При `0 / n` показываем измеренный ноль.

**Приёмка.** Для тестового набора сходятся вычисления вручную, при добавлении наблюдения упоминания изменяются на 1, другой клиент не меняется. Пройдены `npm test`, `npm run build`; отчёт в PR включает фактические числа и даты.

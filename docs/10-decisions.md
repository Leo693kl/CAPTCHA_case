# Журнал решений

## Р-01. Продолжаем существующий прототип

**Статус** — рекомендация по результатам аудита от 19.11.2026. База `fafd69a`.

**Основание.** В коде есть все семь областей минимального функционала, история и редактирование требуют усиления. Текущие тесты проходят. Нужное новое поведение сосредоточено в источниках наблюдений, метриках и интерфейсе карточки. Граница интеграции с действующим графом уже существует.

| Вариант | Что даёт | Что может сорвать сдачу |
|---|---|---|
| Точечно доработать | Сохраняет граф, линзы, сценарии, расчёты и тесты | `App.tsx` управляет несколькими потоками. Нужен один владелец стыков и ограниченные изменения |
| Переписать с нуля | Можно переустроить состояние под новую модель | Придётся повторить проверенную раскладку, редактирование, фильтры, хранение, обмен и демо до сдачи |
| Показать текущую версию | Есть базовая защита кейса | Интервью, обратная связь, конкурентный контекст и метрики не образуют заявленный командой сценарий |

**Проверка выбора.** До массовых правок на одном клиенте пройти выбор → фильтр → карточку → изменение → перезагрузку → локальный diff. Для нового контракта сначала провести одно наблюдение до карточки и вычисляемого числа. Если добавка ломает базовый сценарий, изолировать её в отдельном PR и сохранять рабочий демонстрационный маршрут на интеграционной ветке.

## Р-02. Карта для существующей CRM КРОК

**Статус** — ограничение пользователя и кейса. CRM КРОК остаётся системой-источником в концепции. Синтетические данные, локальный адаптер и экран обмена покрывают показ импорта, собственных данных карты и возможной обратной записи. В интерфейсе явно указать тестовый режим. Собственную CRM, коннектор Битрикс24, сервер синхронизации и API LLM в объём сегодня не включаем. Источники — [кейс](case.md), [указание Виктора и материалы](13-sources.md).

## Р-03. Что переносим из переписки

**Статус** — рабочая трактовка уточнения Виктора. Новые задачи опираются на идеи остальных участников и записанный пересказ встречи. Материалы D прочитаны как история проекта. Специфичные предложения D, включая Битрикс24, DS/ML по стенограммам и его отдельный HTML-макет, не становятся заданиями. Уже реализованные охват, белые пятна, риск зависимости и историческая карта остаются, поскольку у них есть самостоятельное основание в кейсе и в текущем коде.

## Р-04. Объяснимые синтетические наблюдения

**Статус** — предлагаемый контракт. Коммуникационные предпочтения берём из явно записанных ответов и показываем их с источником. Открываемость и упоминаемость считаем по проверяемым записям с явно указанным знаменателем и периодом. Сравнение с конкурентом привязано к интервью конкретного контакта. Выводы не перезаписывают роли и оценки автоматически. Модель и правила — [данные](03-data-model.md#контракт-для-доработки), критерии — [спецификация](11-prd.md).

## Р-05. Один интегратор и отдельные PR

**Статус** — рабочий порядок на сегодня. Виктор ведёт общие решения и слияние. Исполнители работают в непересекающихся владельческих зонах и возвращают короткие отчёты через PR. Причина — основной экран, общие типы и API связывают все потоки. См. [порядок работы](14-workflow.md).

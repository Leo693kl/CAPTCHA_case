# Модель данных

Типы описаны в `src/types.ts`. Все идентификаторы — строки; даты в данных — строки вида YYYY-MM-DD. Числовые ограничения применяются в формах, но сами типы TypeScript не ограничивают диапазон.

| Сущность | Поля и смысл |
|---|---|
| Company | `id`, `name`, `industry`, `initiative`, `description`: идентификатор, имя, отрасль, инициатива, описание; все string |
| Person | `id`, `companyId`, `name`, `department`, `title`, `owner`: string; `decisionRole`: Role; `stance`: Stance; `influence`, `warmth`: number; `interests`: string[]; `consentMarketing`: boolean |
| Relation | `id`, `companyId`, `from`, `to`: string; `type`: RelationType; `strength`: number |
| Interaction | `id`, `personId`, `date`, `channel`, `ourOwner`, `ourDepartment`, `summary`, `sentiment`: string |
| PersonSnapshot | `personId`, `date`: string; `person`: Person; `deleted?`: boolean |
| CRMData | массивы `companies`, `people`, `relations`, `interactions`, `snapshots` соответствующих сущностей |

Role: `decision_maker`, `influencer`, `evaluator`, `user`, `blocker`. Stance: `champion`, `supporter`, `neutral`, `skeptic`. RelationType: `reports_to`, `works_with`, `informal`. В формах оценки — 1–5; подразделения: ИТ, ИБ, Закупки, Финансы, Бизнес, Прочее (`src/types.ts`, `src/App.tsx`). Отдельной сущности Observation нет.

Пример синтетического контакта из `src/data/crm.json`:

```json
{"id":"bank-p0","companyId":"bank","name":"Александр Белов","department":"ИТ","title":"Руководитель ИТ-направления","decisionRole":"decision_maker","stance":"champion","influence":1,"warmth":4,"owner":"Ирина Белова","interests":["Цифровая трансформация","Надёжность"],"consentMarketing":false}
```

В файле три компании, 90 контактов, 87 связей, 270 взаимодействий и 103 снимка: на каждую компанию приходится по 30 контактов, 29 связей и 90 взаимодействий (`src/data/crm.json`). Банк демонстрирует облачную платформу, ритейл — платформу данных, промышленная группа — модернизацию инфраструктуры; подробные авторские замыслы сценариев требуют уточнения.

При создании контакта форма требует имя, должность и владельца; форма связи запрещает выбрать одного человека дважды. Удаление человека удаляет его текущие связи и добавляет снимок удаления, но не удаляет взаимодействия (`src/App.tsx`). Импортированные и сохранённые JSON-данные не проходят полную runtime-валидацию; некорректный JSON заменяется базовыми данными при обработке ошибки (`src/api/crmApi.ts`).

## Контракт для доработки

Предлагаемое расширение `Interaction`. Интегратор проверяет и закрепляет типы одним commit в T00 до слияния потребителей. Текущие поля, ключи хранилища и структура JSON сохраняют совместимость.

| Поле | Тип | Семантика |
|---|---|---|
| `opened?` | boolean | Только для канала «Почта». `true` — есть открытие, `false` — измерено без открытия, отсутствует — сведений об открытии нет |
| `evidence?` | `InteractionEvidence` | Подтверждённая запись интервью либо обратной связи со ссылкой на источник внутри истории |
| `evidence.kind` | `'interview' \| 'feedback'` | Тип источника. В интерфейсе — «Интервью» или «Обратная связь» |
| `evidence.sourceLabel` | string | Читаемая подпись синтетического источника. Дата, автор/команда и содержание уже есть в `date`, `ourOwner`, `ourDepartment`, `summary` |
| `evidence.mentionedPersonIds?` | string[] | Явно выбранные контакты той же компании. Одно упоминание человека на запись |
| `evidence.preferences?` | `{ channel?: string, format?: string, topics?: string[] }` | Только явно названные предпочтения. Видны дата и источник, допускается пустое значение |
| `evidence.competitor?` | `{ name: string, outcome: 'current' \| 'previous' \| 'unknown', reason?: string }` | Слова участника со ссылкой на интервью. Пустая причина допустима |

`InteractionDraft` — состав обязательных полей взаимодействия без `id` с теми же необязательными полями. Id присваивает интегратор при записи. Для повторного сохранения того же предложения передаётся неизменный id уже созданной записи либо блокируется повтор в редакторе. Валидация до записи проверяет наличие контакта в выбранной компании, календарную дату до или включая текущую, непустые источник, автора и содержание для наблюдения, валидные ссылки и диапазон. Пустой или отсутствующий массив трактуется одинаково. Старые сохранённые данные читаются без миграции обязательных полей.

**Метрики.** Общий период — последние 30 календарных дней включительно относительно выбранной даты. Сначала отобрать записи компании и действующей даты. На карте показатели по компании не меняются от фильтра людей, область подписана явно. В карточке открываемость считается по письмам этому контакту, упоминаемость — по упоминаниям его участниками той же компании. В счётчике упоминаний одна запись может дать по одному упоминанию нескольким разным людям. Упоминаемость — число подтверждённых записей с упоминанием из числа подтверждённых наблюдений в области и периоде. Открываемость — `opened === true / письма с определённым opened`. Полученные измерения показываются в виде `a / b` и процента для открываемости с одним правилом округления. При нулевом знаменателе — «Нет данных». Пример `2 / 3 → 67%` задаёт округление до целого.

**Потоки.** Подтверждённое наблюдение становится взаимодействием в рабочей копии и остаётся в ней после перезагрузки. Карта восстанавливает предпочтения и историю из записей до выбранной даты. Для локального diff показать факт добавления или правки взаимодействия. Текст и структурированные поля синтетических записей могут появляться в локальном объяснении обмена. Реальный формат обратной записи и допустимость хранения исходного интервью определяет владелец CRM КРОК в отдельном этапе.
